The executable implementation is [`android_wide_slot_patch.bf`](android_wide_slot_patch.bf). Its complete executable language is the original eight Brainfuck instructions. This stage is Linux-executed under the native BF self-hosted compiler; it is not an Android-hosted compiler.

## Inputs and outputs

The input byte stream is `count8 | wide-encoded-records | 00 00 | count8 * 48 native template bytes`.

- `count8` is the **verified** number of instructions, in `0..74`.
- Each matching pair's 15-byte record comes directly from the BF-native wide encoder: `5D | open24 LE | close24 LE | forward B32 LE | reverse B32 LE`.
- The zero delimiter and zero status are emitted by the BF-native encoder. The upstream BF metadata/pairing stages reject malformed Brainfuck brackets and verify nesting.
- Each 48-byte template comes from the BF-native AArch64 slot emitter. Bracket templates reserve byte offsets `8..11` for the encoded unconditional `B` word, following an `LDRB` and inverted `CBNZ` or `CBZ`.

The patcher outputs `count8 * 48` **fully patched** native slot bytes followed by `00 00`. The BF-native fixed 74-slot ELF wrapper consumes these slots. The host adapter checks boundaries, status and provenance and transfers bytes; it never calculates or rewrites instruction words.

## Tape and algorithm

Control cells 0–9 store the current record, slot count and scratch. Starting at cell 32, the BF stage initializes a 74-entry table, each with eight cells: a travelling count, a leftward sentinel, a patch-present flag, four encoded native instruction bytes, and a per-slot output flag. Only entries after the first have their sentinel set.

For each valid pair, it copies the one-based opening or closing index, converts it to a zero-based index, and walks eight tape cells at a time with a **travelling BF counter**, then reads the four instruction bytes directly into that slot. Sentinel-guided return restores the table base. This avoids external source-position-to-byte-offset arithmetic or external patching. The final pass streams each template through the table. Only slot byte offsets `8..11` are replaced for bracket positions, with conditional branching performed by BF itself.

## Trust boundary and limitations

This is **a trusted-stage protocol**, not a standalone hostile-record validator. The adapter must supply only well-formed status-zero records generated by the verified BF matcher/encoder, one-based positions within the 74-slot bound, and exactly 48 bytes for every slot. Malformed arbitrary patcher input is not a supported contract and may yield invalid output; do not expose this stage directly to untrusted records. A generalized safe backend must add complete internal validation before raising its maturity level.

The extended path remains a **fixed 4,192-byte** Android ELF image with 74 slots and trailing NOP padding, not a dynamic ELF compiler. It has not been executed on Android; the tests simulate AArch64 at two load biases. Android-native compiler execution, Android S2, 300,000-command image emission, all-ABI Android support, and Windows PE codegen are not implemented.
