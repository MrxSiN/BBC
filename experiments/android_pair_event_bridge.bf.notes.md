## Interface and verification boundary

The BF stage consumes trusted framed five-byte bracket occurrences generated by the existing standard-BF source scanner. It maps opening/closing bracket tags and expands four-byte command positions to eight-byte records by adding zero high bytes, propagating the original scanner status. The host does not recognize bracket syntax in this bridge. Upstream offsets remain 32-bit; actual 64-bit generic LIFO records can independently carry larger values. Run `python3 tests/verify_android_dynamic_stack.py`.

**Non-claims:** no new Android loader execution, no JNI-loaded shared library, no general dynamic ELF, no long-distance native branch relocation, no original application policy compilation, and no full 100-million-command executable. Linux-native verification and test-oracle AArch64 simulation are labeled separately.
