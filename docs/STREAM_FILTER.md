# Streamed Brainfuck input filtering — Iterations 13–16

Historical scope: the separate filter predates Iteration 19. The **current** authoritative compiler filters ignored text internally and has a 16,128-command ceiling. The standalone tool remains useful as an independent BF implementation. The new experiment is a separate **816-instruction Brainfuck program** (originally 1,031 instructions) in `experiments/stream_filter.bf`, not another authoritative compiler.

## What works

Unlike the earlier 862-instruction, one-byte-length experiment, this filter consumes the **actual compiler transport**: an EOF-terminated stream where original NUL is `FF 01` and original `FF` is `FF 02`. It outputs only the eight command bytes `><+-.,[]`, followed by a single status byte: `00` on success or `01` on malformed escape. It uses a fixed set of tape cells and can handle input well beyond 255 bytes without buffering the source. Literal zero in the *encoded* stream cannot be distinguished from EOF under the chosen Brainfuck execution semantics; transport clients must honor the stuffing contract.

The filter checks eight byte values using normal BF arithmetic and conditional loops. It checks `FF` escapes separately and stops with a nonzero status if the following byte is not `01` or `02`, including premature EOF. If the source is malformed after a valid prefix, command bytes may already have been emitted: the transport must discard them when the final status is nonzero.

Run:

```sh
python3 tests/verify_stream_filter.py
```

**Executed evidence:** 189 native-filter inputs, including all 256 source byte values, the annotated compiler, 16,001 BF commands, and over 20,000 ignored source bytes; 16 independent seed comparisons; six invalid escape rejections with both seeds; and three paired comment-invariance compilation comparisons. All compiled native filter bytes are generated by the existing Brainfuck compiler. No Python/C code parses or filters the source inside the test chain.

In a **test-only two-process chain**, the native BF filter's output is transported into the existing native BF compiler. Commented and command-only source then produce identical ELF bytes, even if the original comment-heavy source exceeds the production compiler's 16,128-byte raw input ceiling. The chain also compiles the filtered `core.bf`, runs that native compiler, and gets a byte-identical next stage. The BF logic works in the chain; the required single-compiler integration is still absent.

## Why this is not shipped as the compiler

`compiler/core.bf` has only 112 raw bytes of self-compilation headroom. Its decoder, buffered source length, ELF file-size arithmetic, 32-byte slot count and bracket offsets all operate on the *decoded raw bytes*. Simply pasting 816 Brainfuck commands into it exceeds that headroom and does not update those invariants. The test harness may link two existing BF executables by byte-stream transport, but that external orchestration is not a substitute for compiler-owned filtering.

The next production step is to refactor the BF decoder to retain only validated commands, update one canonical command count, and prove buffer and relocation correctness. Repeat native Stage 0–2 self-compilation, including input boundary tests, before marking comment-independent artifacts implemented.

## Iteration 16: smaller native Brainfuck filter

The filter now has **816 executable Brainfuck instructions** instead of 1,031. The original, unmodified 1,031-instruction source remains at `evidence/history/iteration15/stream_filter.bf` for byte-for-byte differential testing. The reduction comes from cumulative byte-comparison deltas; an early-match guard avoids copying a wrapping byte across every later check when common Brainfuck instructions occur. No host-side filtering is involved.

The generated filter ELF changed from **34,839 to 27,959 bytes**. In addition to the existing 189-case streamed test, `tests/verify_stream_filter_equivalence.py` compares both native Brainfuck versions across **390 valid inputs and 10 malformed byte-stuffed inputs**. Its nine interleaved runs per binary on two workload shapes are recorded as measurements, not a performance guarantee. The compiler itself and the format/transport contracts have not changed. The remaining 112-byte self-compilation headroom is insufficient to paste 816 instructions into the core.
