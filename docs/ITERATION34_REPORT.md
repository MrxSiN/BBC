# Iteration 34 — bounded four-class Android ELF generation

## Implementation

Added a Brainfuck-only relayout stage and an opt-in `--multiclass` branch of `bootstrap/run_android_extended.py`. The source is [`../experiments/android_multiclass_elf_relayout.bf`](../experiments/android_multiclass_elf_relayout.bf); its implementation and limits are detailed in [the source notes](../experiments/android_multiclass_elf_relayout.bf.notes.md). It reuses the existing BF scanner, native slot emitter, BF bracket matcher, wide branch encoder, BF 512-index patcher and BF page-class image writer. All new executable-layout decisions and image bytes are generated by the new BF stage. The Python adapter performs only validated byte-framing and atomic file placement.

**New mode:** `python3 bootstrap/run_android_extended.py source.bf output.elf --multiclass --loops`. Linear sources work without `--loops`. The new limit is **1024 executable BF commands**, including bracketed programs with maximum loop nesting 255. This is **not** general 300,000-command compilation.

The BF stage rounds `0x220+48n` up to a 16 KiB-aligned RW file offset, recomputes the dynamic segment offset and emits padding before copying the 96-byte tape/dynamic trailer. New transitions are at **672** and **1013** BF commands, with full image sizes **49,248** and **65,632** bytes. Up to 512 commands, new output is intended to be byte-identical to the previously verified page-class image.

## Verification

The authoritative Linux BF compiler remains untouched. The new BF source compiled to a native Linux ELF. Use the evidence-backed [focused test](../tests/verify_android_multiclass_elf.py), [evidence record](../evidence/iteration34_multiclass_elf.json) and [current handoff](HANDOFF.md). This is **Linux-executed BF code and AArch64 simulator evidence only**. No Android loader/device testing was possible on this host. Do not upgrade Android maturity or claim Android-native compiler execution or self-hosting.

The first unconstrained randomized loop-fixture attempt hit its execution-step limit. A revised terminating bounded randomized corpus then passed its semantic/simulator checks. An independent seed-interpreter attempt for the smallest ELF relayout exhausted a 75-million-step budget: **inconclusive**, not a mismatch or pass. See the machine-readable record for counts from the final run.

## Unchanged / deferred

- Linux x86-64 canonical BF compiler and its existing self-hosting evidence are preserved; fresh Stage 1–2 replay status is recorded separately when executed.
- The legacy 74-command, dynamic 255-command and page-class 512-command modes stay available.
- The code segment and tape rely on a fixed tape virtual address; further scaling past 1354 BF commands will require a BF-authored tape placement and startup change, not simply a larger frame count.
- Android-native self-hosting, the planned 300,000-command test, Windows PE32+ backend and independent cold bootstrap remain outstanding.

## Next

Provide a BF-authored generalized ELF layout with tape relocation and position-independent startup beyond the current fixed `0x10000` tape page, then test larger loop programs in an actual Android supported shell. Continue Android before Windows as the documented project plan requires.
