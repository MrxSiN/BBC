# Iteration 65 — Disk backed callable relocation bookkeeping

## Change

The active resource scaled callable AArch64 path no longer keeps a Python `set` of every BF generated relocation word index. `bootstrap/android_compact_far_relocated53.py` now tracks previously patched indices with one bit per native word in an automatically removed sparse temporary file. The underlying BF stages still produce the native bytes and signed 64 bit relocations. Python only uses the BF supplied index to read and write an opaque eight byte literal and to reject reuse of an output location.

Each eight byte relocation occupies two native words. Both are marked, so partially overlapping literals are rejected even if the existing literal happens to contain zero bytes. The temporary file grows as needed. There is no new program size or nesting ceiling. Actual RAM, disk space, host file offset limits and compilation time still apply. A full temporary file or an unsupported file offset remains a build failure rather than permission to overwrite another relocation. The previous output is replaced only after the existing ELF and instruction checks pass.

No authoritative `.bf` source or native BF stage binary was modified. The BFP1 callable ABI and generated machine code remain unchanged. This is a transport resource scaling fix and does not establish Android native self hosting or an Android loader result.

Iteration 65 generated five complete DSOs matching hashes from the unmodified iteration 64 relocation path. It also compiled 12,000 adjacent zero cell loop pairs with 24,000 BF generated wide relocation patches and a 1,056,108 byte native code section. Two AArch64 simulator/reference comparisons passed. A deliberately duplicated BF patch record was rejected without changing the existing destination image.

The isolated host storage test wrote 50,008 unique marks, including an index beyond 32 bits, and verified duplicate and four overlapping patch rejections. The separate 50,000 mark loop peaked at 4,914 Python `tracemalloc` tracked bytes. This measures **only** duplicate tracker allocations, not the peak memory of the compiler pipeline, OS buffers, or BF stage processes. The disk backed tracker uses one bit per native word of logical storage plus filesystem allocation overhead.

The iteration 59 DSO tests, iteration 63 960 differential comparisons, iteration 64 104 simulator comparisons, nine loader fixture simulations, and nine JNI host stub cases passed in the same session. The three archived real BF sources for Gmail `row`, Gmail `scope` and Twitter `action` again generated byte identical DSOs. Two Linux native compiler self compilations were byte identical. The full cold bootstrap was not rerun and the long iteration 58 suite was not rerun in this iteration.
